# OEv1 计划沿革与当前方法澄清（2026-09-06）

> 核心方法始终是 OEv1：在 RGB 检测训练中，对可靠且具有相对优势的 IR 对象判别证据进行选择性蒸馏。此次变化是验证范围和资源优先级；不是读出结果后改损失。本文只读梳理到 23:25 已完成记录，实时训练/调度以本目录 README 与操作回执为准。

## 当前究竟在做什么

- 当前原创候选：Object Evidence v1，简称 OEv1。它是工作名称，文献新颖性和实验有效性尚待验证。
- 主任务：DroneVehicle，训练期 IR 教师 + RGB 参考辅助 RGB 学生，部署期仅 RGB YOLO11n。
- 教师与参考均固定为已训练 seed42 模型；只训练 RGB 学生。RGB/IR 各自真实标注建立同类对象对应，IR 标注是额外训练信息。
- 知识：P3/P4 上正确类别原始 logit 的前景 logmeanexp 减局部背景 logmeanexp，除温度 2，得到对象相对背景的判别证据。
- 选择：基础对象需真实对应、区域有效、RGB 参考已有粗候选；进一步要求 IR 教师正确且证据代理优于 RGB 参考，按优势取合格对象前 50%。
- 损失：选中对象的证据 SmoothL1，教师目标截断到 [-8,8]，按筛选前基础集合大小归一，权重 0.1，加入 RGB 原生检测损失。
- 当前没有全图特征 MSE、DFL/框蒸馏、亮度门控、可学习模态子空间、额外推理网络。冻结 RGB 参考的候选只是可学性代理，尚不保证当前学生不会受损。

关键区别：**从首轮 OEv1 到三 seed，再到 paired_random，原 P/N 的知识定义、阈值、λ/ρ/T、训练预算、评估端点均未改变。** 改的是种子数量、补充对照、排程与支线投入。随机选择是另一实验臂，用于解释 OEv1，不是替换 OEv1 主方法。

首轮设计曾列出“对象类别响应”和“相对背景证据”两种知识候选；正式训练前固定后者。不能描述为读出训练 AP 后换知识。随机选择实验冻结时已见到部分 P 端点，日志明确标为后续机制实验，不追溯称与首轮同时预注册。

## 原本要验证的链条，以及还差什么

| 层次 | 对照 | 当前状态（23:25记录） | 作用 |
|---|---|---|---|
| 净收益 | P 对同代码 weight0，三 seed | 6 个正式 run 中 3 个已独立评估、3 个续训；暂缺完整同 seed 对 | 整套干预有无实际收益 |
| 选择机制 | paired_random，同 E、同 K、同 λ、同分母 | 实现和 seed42 canary 通过，seed42 E200启动，0/123原队列串行 | 检验教师可靠性＋质量选择整体，不能单独归因 q 排序；等名义剂量不等实际梯度 |
| 同模态来源 | same-modal | **尚未实现成正式可执行长训** | 是否超过 RGB 教师的普通蒸馏；不能让 teacher 与参考完全相同使 q 恒为0 |
| 配对内容 | 合理 shuffled / donor | **尚未实现、未启动** | 真实对应信息是否有价值；不能用错配导致零候选作失效对照 |
| 额外标签 | GT-only、同选择 mask | **尚未实现、未启动** | 分离教师软知识与额外 IR 标注/难例加权的作用 |
| 外部方法竞争力 | CMDistill-corrected | 已有三 seed 独立端点 | 协议适配的全量蒸馏参照 |
| 外部方法竞争力 | CCLKD partial | 已补齐三 seed 独立端点 | 实际仅 LLD+CCL，不能称完整原论文复现 |
| 新增强外部对比 | FGD | **列为下一优先项，尚未实现或启动** | 与前景/背景、注意力和关系知识的成熟方法比较 |
| 第二数据集 | LLVIP | 有 baseline/诊断，OEv1 正式训练尚未启动 | 主方法获得净收益及机制证据后检验扩展性 |
| 扩大问题范围 | VEDAI | 近期暂缓 | 保留 NIR/反向教师/小目标诊断，不追加当前训练 |

首轮从来不是“只做 P/N 就论文完成”。三 seed 净收益、paired/shuffled/same-modal/native 归因是原先的证据要求；本次把 random 和外部方法提前补齐，是完善该验证链。

## 单卡并发的准确规则

用户当前 AGENTS §2.2 原文是“每张卡最多 3 个任务”，**允许单卡多开**。§2.1 的 3 卡上限（满足放宽条件可4卡）限制的是同时使用卡数，不能理解成每卡只允许1个训练。

早期 N/P 串行是当时首轮的保守执行安排：用户只授权一张 GPU，计划还考虑卡上已有其他研究 CUDA 任务；三 seed 扩展沿用了每条队列一次一个训练。它们是历史排程，不能覆盖当前用户规则或推导成不允许并发。

当前该按实际显存、任务数量、总内存与吞吐决定能否加任务。单进程 canary 6304MiB 和训练期约7.6GiB只是已有测量；不能简单按24G除以数字，声称三开一定安全。单卡最多3任务、加入后留至少2GB、总RSS≤300GB、实测 canary 仍须同时满足。并发后不改变 batch/训练预算/方法参数，仅调整排程和资源审计。
