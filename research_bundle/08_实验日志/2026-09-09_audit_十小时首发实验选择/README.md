# 十小时预算下的首发实验选择（2026-09-09）

**建议首发：DroneVehicle、C1批量化加速实现、seed42、完整E200，固定末轮EMA并独立评价1469张dev。先补同一个run的自动评价及10小时硬预算，再启动；不重新做方法筛选子集，也不先重训尚未通过显存准入的作者大模型。此条目为核对与排程建议，本轮没有启动GPU实验。**

## 为什么优先这一项

1. 这项方法已经实现，选择与损失测试、真实raw对照及连续100次optimizer更新有既有证据。94的加速代码、三seed配置、初始化、IR教师、RGB参考和评价入口本轮均只读确认存在。
2. C1旧三seed在重启前仅完成约77/80/77轮，没有正式E200末轮结论。此前E8和成熟起点FT3未验证能预测E200排序，不能据它们直接淘汰C1，也不应继续增加同类代理试验。
3. 同协议N/C0已有完整三seed，可直接回答“扩大分类载荷后，最终精度是否优于原方法”。不用为了启动C1先重做六份基线；比较保留执行实现及浮点轨迹差异的限制。
4. 只有这条新增方法路径已有接近10小时预算的完整训练短窗实测。选择它是为获得目前缺失的完整训练证据，不代表已经证明C1成功概率高。

近期用户要求的“先原文协议，再迁移”继续适用于外部方法：CFT和LLVIP作者权重复评已完成；作者从头训练仍有资源/成本问题。本建议让我们已实现的原创候选优先使用可满足预算的GPU时段，暂不让不合预算的重型重训占首位；不新增未经原文核查的迁移版对比，也不依据其负结果判断作者论文。

## 启动前只补两个执行缺口

本轮15:12–15:13只读确认：现有production_release_v2及相关权重/评价入口仍在94；三个加速正式output均不存在。原计划明确 `automatic_evaluation_in_this_launcher=false`；实际入口仅输出评价待完成字段，源码没有run级10小时deadline。dispatcher的5秒/3秒timeout是进程回收等待，不是训练预算。

1. 在独立的新启动包装中，把训练和随后独立dev评价串成一个run，共用现有全局lease并保证训练进程退出后再评价；记录训练、保存、评价分项及总时长。训练失败时不把部分checkpoint评价算作完整E200。
2. 增加run级deadline和工程预算检查，不修改训练配方。预算只读耗时/资源，不读取AP决定是否继续。超过预算保留产物并标记预算中止；未完成E200和评价就不记为完成结果。不能静默延长到第二天，不能缩轮数或缩数据后仍标E200。

不另建调度器，不重写已验收C1算子。原冻结入口和失败attempt不覆盖。

## 将速度检查放进首个正式run

首个run从一开始就是原E200日程。记录前5个自然epoch的整轮墙钟，覆盖3轮warmup及其后更新节拍，并记录epoch保存/原观察开销；这些更新直接属于这个run，符合预算就继续原进程，不另建E5方法实验、不换起点重训。

用已消耗时间、最近完整epoch成本、余下轮数、保存/评价预留量更新预计总时长。0.28秒/批是辅助参考，整轮预计总量是实际准入依据；若预计不能留出保存/评价余量则因工程预算中止并排查，不能据前5轮AP淘汰方法。10小时deadline仍是硬限，预计值不构成保证。若不能在10小时内完成，报告执行预算失败，不报告C1方法失败。

## 后续顺序与结果判定

1. 首发C1-fast seed42。速度及资源检查通过后，seed0可在另一张空卡开始，seed123随后排队；先按每卡一个项目训练，不借双开增加单run耗时。
2. 三seed继续按原计划完成，不因为42的中途或末轮AP不理想取消0/123。每个run各有10小时上限；三个seed是三次run，不能承诺合计10小时或简单按GPU数相除。
3. C1−N三seed全正且均值至少+0.10pp是效用投入门；同时C1−C0三seed全正且均值至少+0.10pp，才进入C1替代及C1_y内容消融。0.10pp不是显著性证明。其他AP50/逐类损伤复核条件保留，不现场改阈值。
4. 最终保留C0、C1或条件消融后的版本，再补它的shuffled/same-modal三seed归因。C0的已有小幅收益仍是保留起点；其旧归因部分checkpoint不是完整结果。控制臂必须另有加速/资源验收，不能直接借C1速度承诺10小时。
