# OEv1 与选择性定位蒸馏的代码可行性审查（2026-09-07）

> **结论：定位分支在现有 YOLO11n 框架中可实现，但不是把 OEv1 的类别和定位条件对调即可。第一版适合验证“身份可信、学生有候选、教师在学生坐标系中确实更准”的对象；未通过 NMS/置信阈值不等于不能蒸馏。未确认几何映射和对象身份时应跳过定位 KD，保留原生 RGB GT 监督。本文为可行提案，不是已实现或已验证结果。**

## 1. 当前 OEv1 实际选择什么

| 环节 | 实现 | 对方法解释的约束 |
|---|---|---|
| 双模态对象关联 | RGB GT 与 IR 独立 GT 同类且 IoU≥0.5；先最大化有效匹配数量，再最大化 IoU 的 Hungarian 一对一分配 | 同一文件、同类不等于同一物体；该关联是几何代理，不是实例身份真值 |
| RGB 可学性门 | **冻结 RGB reference** 的 pre-NMS 候选，最大类别 sigmoid≥0.05，候选对 RGB GT IoU≥0.1 | 不要求 reference 预测类别正确，也不要求定位达到 IoU0.5；不是动态学生已准确检出 |
| IR 教师门 | pre-NMS 候选正确类别为 argmax、该类 sigmoid≥0.25、对自身 IR GT IoU≥0.5 | 教师的正确性在 IR 坐标/标签中成立，并不自动意味着框可直接监督 RGB |
| 判别质量 | `q=max(softplus(-e_reference)-softplus(-e_teacher),0)`，合格对象中取前半 | q 是相对证据排序代理，不是校准误差或定位质量 |
| 蒸馏目标 | 各自在本模态 GT 内的正确类 log-mean-exp，减去排除所有 GT 后的局部背景 log-mean-exp；P3/P4 共有效层平均、温度2、SmoothL1 | 没有直接蒸馏框、DFL、完整类别分布，亦没有独立 objectness 蒸馏 |

因此，把当前 OEv1 描述为“学生定位准时蒸馏类别和置信度”过强。准确说法是：**RGB 参考已有粗候选时，对 IR 教师可靠且具有判别优势的共同对象，蒸馏对象相对背景的正确类证据。** 当前学生的 raw scores 接收梯度，参考模型提供固定筛选依据。

YOLO11 检测头在快照中输出 `nc + 4*reg_max` 通道：`scores[B,C,A]` 和 `boxes[B,4R,A]`。推理把 box 解码结果与 `sigmoid(scores)` 拼接；没有额外 objectness 通道。“类别/置信度准”需拆成类别是否正确、分数是否可靠两个问题，高分本身不能证明定位准，也不能证明概率已校准。

## 2. “反过来蒸馏定位”的必要条件

用户提出的互补思路合理，但逻辑条件应是：**学生有可归属且可学习的对象候选；教师对该对象的定位在学生目标坐标系中更可靠。** 学生类别正确或高分可以帮助寻找候选，却既非充分条件，也非定位学习的数学必要条件。

需分开三个判断：

1. **身份可信**：IR 对象、RGB GT、RGB 接收梯度的候选均指向同一实例。
2. **定位优势可信**：映射后的教师预测框优于 RGB 参考/学生框，而不仅是 IR 教师对自身标签 IoU 高。
3. **学生可学习**：RGB 中存在可用外观/边界线索，或至少存在不含混的有效正样本。冻结 reference 候选只能作为代理，不是可达收益证明。

从两个分支的关系看，这是“按任务质量路由知识”的可测试假设；增加 box KD 并不能自动成为独立创新点。可发表贡献还取决于身份/坐标处理、错误分解依据、负迁移控制和真实实验证据。

## 3. 学生没检出，是否就没有蒸馏位置

**没有后处理检测框，仍可能有可蒸馏的 dense 候选。** 框架原生训练就是在未做 NMS 的 dense 预测上，利用 RGB GT、anchor center、类别分数和预测框质量构造 TaskAlignedAssigner 正样本。`utils/loss.py:402` 的 `get_assigned_targets_and_loss` 已返回 `fg_mask/target_gt_idx/target_bboxes/anchor_points/stride_tensor`，因此不需先让模型产生最终检测框再训练定位。

| “未检出”的原因 | 定位 KD 可行性 | 建议处理 |
|---|---|---|
| 候选框存在，正确类别分数低于0.25 | 有接收梯度的位置；可能主要是判别错误 | 检查候选定位，再决定 class、box 或两者；不因分数低直接排除 |
| 框/分数本身良好，被相邻目标 NMS 或分配竞争压掉 | 可用 raw 候选，但身份容易混淆 | 用 GT 分配和一对一/冲突约束；勿按后处理“漏检”给整个对象贴定位差标签 |
| 类别正确/高分，框偏移或尺度不准 | 定位分支最直接的候选组 | 必须有教师映射后更准的证据，保留同 mask 的 GT-only 对照 |
| RGB 参考没有粗候选，但 native assigner 仍可分配 | 数学上可优化，跨模态收益尚不确定 | 第一版可保守跳过额外 box KD；记录“可分配但无参考候选”覆盖率，作为后续单独消融 |
| 完全遮挡、模态中没有目标可见线索、无 GT 对应或候选身份含混 | 可强行加梯度不代表存在可迁移知识 | 跳过跨模态定位 KD；学生原生 RGB GT 监督仍保留，不删除该样本 |

不能把“无最终检测框”直接等同于“RGB 中物理不可见”，也不能反过来把“任意 dense anchor 都有框输出”当作对象身份已经建立。对拥挤图中的同类相邻车辆，一个宽松 IoU0.1 的框可能同时覆盖多个 GT；当前 `_has_candidate` 只是 `.any()` 存在性判断，没有输出唯一候选 ID，也不禁止同一候选支撑多个 GT。新增定位分支必须补充对象到学生 anchor 的明确分配。

## 4. 跨模态身份和坐标是两个独立问题

当前 loader 按显式图片映射/唯一文件名配对，独立读取两侧标签，并回放相同平移、缩放、翻转 RNG。它保证增强几何一致，**不校正采集时的视差、局部错位、热轮廓与可见轮廓差异**。

当前同类 GT IoU≥0.5 的 Hungarian 匹配可处理一对一竞争，但没有显式实例 ID、外观核验、双向唯一候选或匹配间隔检查。局限包括：

- 大错位使正确实例的 GT IoU 不足0.5而被丢弃；一味降阈值又增加相邻同类物体互换风险。
- 拥挤车辆/行人可能有多条几何近似边，最大总 IoU 不保证物理身份正确。
- 遮挡导致两侧标注外延不同，或只标了热可见/可见部分；这既影响匹配，又影响“教师更准”的解释。
- 两侧共用同一标签时 IoU=1只是注释来源相同，不能证明图像配准精确。

第一版可使用保守可靠子集：双 GT 一对一关联且无同类竞争/近似等价备选，排除截断和严重标注不一致；有数据集实例 ID 时优先使用。是否“边界可迁移”必须单独做视觉与误差复核，不能仅靠身份匹配通过。

## 5. 为什么不能直接复制 IR box 或对应网格 DFL

对教师网格中心 `a_t`、stride `s_t`，DFL 的第 k 个 bin 表示相对该中心的一侧距离 `k*s_t`，不是绝对像素坐标。即使两个模型都叫 P3、都是640输入，相同网格位置仍可能看到不同物理点。把同索引 DFL 直接 KL 会把场景位移和目标边界差异一起教给学生。

严格的定位传递至少需要：

1. 在教师自身坐标中解码真实教师预测；
2. 用可靠且独立于该对象目标框的映射 `W(IR→RGB)` 转成 RGB 坐标；
3. 在 RGB 中为同一个对象分配学生 anchor；
4. 若用 box 距离损失，比较同坐标中的学生 box 与映射后教师 box；若用 DFL KL，则还须依据学生 anchor/stride 重新投影教师分布、处理边界溢出和有效支持，保留教师的不确定性。

例如左边界的教师随机坐标是 `X_left=a_tx-s_t*D_left`。学生左侧距离是 `(a_sx-W_x(X_left,...))/s_s`。只有坐标系、anchor 和 stride 对齐时才能直接比较原距离分布。一般仿射/透视映射还可能耦合横纵边界，简单独立四边 KL 未必能忠实表示映射后的分布。

**不能用当前对象的 IR GT→RGB GT 专用仿射把教师框强行归一到 RGB GT，再称为纯教师定位知识；更不能直接制造以 RGB GT 为峰值的零熵“教师分布”。** 这会把标签信息和 GT 重权伪装成蒸馏，并掩盖真实几何偏差。校准元数据或训练图像独立估计的共享映射可以考察，但必须冻结、评价误差，且不使用评估集目标框拟合。

在映射尚未可信前，直接复制框的路线应停在离线诊断。可先限定近似已配准区域并明确使用恒等映射的假设；GT 几何一致仅用于审计与筛选，不能作为映射可靠性的唯一证据。

## 6. 最小可实现路线

建议第一版先验证**对象级、选择性的解码框蒸馏**，后续有证据再增加 DFL 分布迁移。二者不是已经启动的实验。

1. 冻结一份新的独立方案，保留现有 OEv1 原样。先以现有 baseline 预测和双 GT 审计候选量、类别/定位四象限、匹配歧义、教师自身 IoU 与教师框映射后对 RGB GT IoU 的差异；完整路由统计需 raw 候选，不能只用阈值后框代替。
2. 使用唯一可靠的 GT 对象关联；选择有 RGB 可学性代理且定位仍有差距的对象。IR 教师正确性、学生坐标系定位质量和相对优势分别检查，门和权重 detach。冻结 reference 版本利于保持跨臂一致；若改动态学生门则需显式登记，这与当前 OEv1 选择机制不同。
3. 以原生 assigner 的对象 ID/正样本 anchor 为学生监督位置，避免每个对象各找一个 `.any()` 候选造成复用。**复用原生分配结果必须保证 native loss 只计算一次**；在新 trainer wrapper 中可调用其返回 assigned targets 的接口，再单次组合原生 loss 与 KD。
4. 增加学生可微 DFL 解码；当前 OEv1 `_decode_boxes()` 开头 `.detach()`，仅适合质量诊断，直接复用会让 box KD 无梯度。教师分支仍 `no_grad`。先采用 IoU/尺度归一 SmoothL1 的真实教师预测目标；不人为把目标变成 GT。
5. 做 CPU 几何/身份反例与 canary：错位、重叠同类、尺度不同、无候选、无有效配对时安全返回可微零；KD 对 student `boxes` 有非零梯度；teacher/reference/assignment 无梯度；权重0与原生 loss/梯度一致。
6. 首要比较 OEv1、定位分支、组合分支及同代码 N；对定位分支必须有同 mask/同剂量 RGB GT-only 重权、same-modal、随机选择与内容打乱对照，按资源和预注册分阶段推进。先验构造的 identity-safe shuffled 不能简单复用不同图的绝对坐标。

额外 IR 标签已被用于身份和质量筛选。RGB GT 已经提供学生的定位真值，教师预测不会凭空提供“更正确的 GT”；定位 KD 的可能价值是软预测结构、误差选择、优化路径或额外模态观测，必须用同 mask 的 GT-only 对照排除普通难例重权。若目标最终接近 RGB GT 而教师细节几乎消失，应如实称为标签辅助/重权，而不是声称发现了新的教师定位信息。

## 7. 可证伪的反例

- IR 对自身 GT IoU0.9，但受6像素视差影响，复制到 RGB 后对 RGB GT IoU0.45；RGB 候选本来0.65。高教师置信度仍会造成负迁移。
- 两辆相邻同类车在两模态中都有高分预测，Hungarian 把 A/B 互换。两侧“类别正确”不提供实例身份保证。
- RGB 框 IoU0.75但分数0.15，后处理未检出；对它主要缺判别证据，追加 box KD 未必解决漏检。
- RGB 类别/分数很好但定位0.35，IR 对自身标签0.8；只有映射后 IR 对 RGB 标签仍明显优于0.35，才构成定位可迁移机会。
- IR 能见而 RGB 完全遮挡的对象：GT 可以定义训练位置，但没有证据保证 RGB 学生从该模态恢复不可见边界；需单独报告，不应让强教师分数压倒可学性条件。

这些反例说明，对称的任务分支是合理起点，实际关键是**哪种错误确实由可迁移的教师信息补足，以及错误坐标/错误身份何时必须拒绝蒸馏**。
